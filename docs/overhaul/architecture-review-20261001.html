R2 · Put session assembly behind a small constructor

Strong in-process

harness/sessions.rs :330–440 · subagent/spawn.rs :100–175 · agent.rs :204–232, :498–531 · agent/testkit.rs · harness/testkit.rs

After — one constructor

Problem: bringing one running session into existence means learning six wiring steps at five sites — the hottest code in the crate (harness/ = 37 commits since 09-20).

  • locality: wiring changes touch one module
  • leverage: one interface, five call sites
  • assembly bugs become constructible in one call
  • test surface stops being the wiring knowledge

R4 · Make the turn-end OM pass one call

Worth exploring in-process

agent/turn.rs :344–460 (om_turn_end) · om_integration.rs :40–130 · om_integration/turn_end.rs :109–290

Before — the turn loop orchestrates OM policy by hand

turn loop: compute pending tokens

turn loop: promote
om: plan
turn loop: build observer request + status strings

After — the policy owns its sequence

turn loop: kill check (turn policy)

Problem: the OM policy — the heart of ADR-0004 — is split between the turn loop (sequence, store reads, status strings) and turn_end.rs (plan/commit); this is where the 80 GB bug lived, and the sequencing is only exercisable by running a whole turn.

Solution: one OmState method — “settle this turn's observations against this store” — owns the whole sequence.

  • the sequence becomes a direct test surface
  • turn loop keeps only turn policy
  • ADR-0004's policy gets a home
