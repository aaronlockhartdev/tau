# Agent GUI layouts — industry research

Research for the tau GUI redesign. Goal: see how shipping coding-agent products lay out their
surfaces (transcript, steering, files, tasks, sub-agents, sessions, settings) to validate our own
design: sessions-first left list, right dock for tasks/sub-agents/files, topbar workspace
switcher, focus mode with edge pill rails.

Method: official sites, docs, changelogs, official screenshots. All sources accessed **2026-10-11**.
Where a detail could not be confirmed from a primary source, it is flagged as unconfirmed.

## Per-product notes

### 1. Cognition Devin (app.devin.ai) — web app

- **Pane structure:** persistent left **sessions sidebar** (collapsible; can be fully hidden and "peeked" on hover) plus the main session workspace. Sessions have a compact page header with tags and hierarchy built in (Aug 2026 release notes).
- **Transcript:** the session **worklog** is the central surface; the **Progress** tab unifies all shell commands, code edits, and browser activity in one timeline. You can click any step to see details. A **side chat** opens in a *panel next to the worklog* (read-only Q&A without interrupting the main run).
- **Files / editor / terminal:** tabbed tools inside a session: **IDE** (embedded VS Code, watch edits live, take over by stopping the session), **Shell** (full command history with output previews), **Browser**/Computer (interactive browser of Devin's machine), **Changes** (persistent file-tree sidebar + full-width diffs), and **PR** tabs.
- **Monitoring:** sidebar lists sessions with status and PR state (multi-PR dropdown), agent-mode icons, origin indicators; **sub-Devin (sub-agent) sessions render as a nested tree in the sidebar**; a **Tasks tab** shows Devin's latest task list for at-a-glance progress; Slack/Teams/email notifications when a session needs input.
- **Navigation:** left sidebar (nav tabs are customizable, group by folder/PR/repo, multi-select tag filters, origin filter) + **Cmd+K command palette** (session search, "start session with prompt", open Devin Review from a PR link).
- **Workspaces/sessions:** sessions are the unit; a home screen surfaces playbooks/snapshots/shortcuts; sessions can be spawned from the web app, Slack, Teams, Linear, Jira, API, or scheduled Automations. A separate **metrics** page (app.devin.ai/metrics) aggregates PR metrics.
- **Focus/immersive:** no documented fullscreen mode; the hideable/hover-peek sidebar is the closest equivalent. Voice mode (live calls with Devin) exists as an input modality, not a layout mode.

Sources: docs.devin.ai/get-started/devin-intro · docs.devin.ai/work-with-devin/devin-session-tools · docs.devin.ai/release-notes/overview (accessed 2026-10-11)

### 2. OpenHands (All Hands AI) — web UI ("Agent Canvas")

- **Current web UI is Agent Canvas** (open-source browser client); the older Docker-based Local GUI is deprecated. The browser UI connects to a backend (local machine, Docker, VM, Modal, or OpenHands Cloud); "the browser UI is where you chat, inspect files, manage settings, and configure automations." A native desktop app preview build also exists.
- **Pane structure:** left **sidebar with the conversation list, grouped by workspace folders** (a bulk collapse/expand-all control on the "Conversations" header); center **chat area**; right-side **drawers/peek panels**: a **Files drawer** (resizable file tree, open-file tabs, workspace path row) and a **Commits drawer** (unified commit history + uncommitted changes, with git actions that send prompts to the agent).
- **Transcript:** center chat with message bubbles; the composer shows a **live activity chip** for the agent's current unresolved action ("reading a file", "running a command", else "Thinking"); context-window meter in the composer with manual compaction; failed-message bubbles with Retry/Dismiss; "Branch from here" on any message forks the conversation; transcript export to Markdown/HTML from the kebab menu.
- **Files / terminal:** Files drawer as above; terminal and file tools run in the backend — the UI inspects results in the file browser. A **conversation overview panel** (workspace info, git state, loaded skills/MCP/automations) **peeks beside the chat area** and closes when the Files drawer opens.
- **Monitoring:** sidebar list with tags (chips like `Key: value`, `+N` overflow), archive/pin, automation-run filters (All/Hide/Only per automation); **child conversations** (launched via `launch_child_conversation`) stay **linked to their parent** with results returned to it; `/goal` runs show a **status banner** (objective, round, judge score, missing work); an **Automate view** lists automations (schedule/event-triggered).
- **Workspaces/sessions:** a *conversation* is one agent session on the active backend, with its own history, agent profile, plugins; its **workspace is the folder/mount/sandbox attached to that backend** — conversations and workspaces are deliberately isolated; per-workspace file-discovery settings.
- **Focus/immersive:** no documented focus mode; the pattern is drawers/peek panels that overlay the chat (overview panel, Files drawer, image lightbox).

Sources: docs.openhands.dev/openhands/usage/agent-canvas/overview.md · .../conversations.md · docs.all-hands.dev (accessed 2026-10-11)

### 3. OpenAI Codex (cloud) — web task UI

- **Where it lives:** Codex is a section *inside the ChatGPT web and desktop apps* — you pick "Codex" in the product selector; the sidebar then focuses on Codex chats and development projects (vs. general ChatGPT chats). The desktop app exposes "developer details, including diff and review views" and an optional **Pull requests pane**.
- **Pane structure:** left **sidebar with projects and chats** (show/hide via command; pinned chats; "Quick chat" entry point), main **task/conversation pane** with the composer. A new cloud task is started by choosing **Work in > Cloud > Select environment** and describing the task.
- **Transcript:** the task conversation in the main pane; follow-up messages steer the task; on mobile you "start, guide, approve, and review Codex tasks on a connected computer from your phone." Exact transcript rendering details (streaming steps, shell output) are not described in the docs I could access — flagged unconfirmed.
- **Files / review:** **diff and review views** for task changes ("Inspect changed files and check results, request follow-up changes, and commit or open a pull request"); a **Pull requests pane** when enabled; cloud environments are configured in their own settings surface (repos, tools, network access, secrets).
- **Monitoring:** sidebar chats carry statuses (idle / thinking / complete-with-unread / requires-input / error — documented via the Codex Micro key-mapping, which mirrors the app's chat states); an **Activity view** (bell in the sidebar) "brings together chats you recently engaged with and work that needs your attention." Tasks keep running in the cloud "while your computer is asleep."
- **Workspaces/sessions:** **projects** keep related chats/files/instructions together; a **cloud environment** (published, reusable: repos + dependencies + tools + network secrets) is the workspace template, and **each task starts in its own isolated workspace**; **git worktrees** let you run chats in parallel. Tasks can also be started from the CLI, Linear, GitHub, or Slack.
- **Focus/immersive:** no documented focus mode; the collapsible sidebar and the Activity view are the relevant mechanisms. (Unconfirmed: any dedicated fullscreen task view.)

Sources: developers.openai.com/codex/cloud · learn.chatgpt.com/docs/features/codex-micro.md · learn.chatgpt.com/docs/codex-manual.md (condensed manual) · openai.com/index/introducing-codex (accessed 2026-10-11)

### 4. Google Jules — web UI

- **Pane structure:** a focused web app (jules.google.com) built around **repos** and **tasks**. The home screen is a **repo selector + branch picker + prompt input** with a "Give me a plan" action; a **left sidebar** is where you enroll/select repositories. There is no file tree or editor — Jules works in an isolated VM and the UI is for planning, watching, and reviewing.
- **Transcript:** each task view has a **chat box** (give feedback, answer questions, revise the plan) next to an **activity feed** that shows each agent step as it completes, with inline explanations of each change.
- **Files:** a **mini diff preview per file** in the feed, plus a **diff editor** for the full view across all files. The final summary lists files changed, runtime, lines added/changed/removed, and offers **Create branch** with a commit message. No in-browser editor/terminal.
- **Monitoring:** the activity feed is the live monitor; the **repo view lists that repo's tasks** (hover a task → pause/delete); new tasks started elsewhere **run in the background** and you navigate to them to approve plans; **browser notifications** fire when a task completes or needs input. A CI-Fixer loop auto-repairs failing checks on Jules PRs.
- **Navigation:** home screen (Jules icon returns you to a blank prompt), **top navigation with a + button** in the task view, repo pages with "new task", left sidebar for repos.
- **Workspaces/sessions:** **repos are the top-level unit** (connect GitHub, choose all/specific repos); each task runs in **its own VM with its own logs, environment, and code changes**; task types: manual, **scheduled**, and **suggested**.
- **Focus/immersive:** none documented in the official docs.

Sources: jules.google/docs/ (getting started) · /docs/running-tasks/ · /docs/review-plan/ · /docs/tasks-repos/ · /docs/changelog/ (accessed 2026-10-11)

### 5. Google Antigravity — agent-first IDE + 2.0 desktop command center

- **Multiple surfaces, one harness:** **Antigravity 2.0** (standalone desktop "command center for your agents"), **Antigravity IDE** (VS Code-based agentic editor), and a keyboard-centric **CLI/TUI** (`agy`). All share the same agent harness, subagents, and artifacts.
- **2.0 pane structure:** **left sidebar with projects** (a folder-with-"+" icon creates a project from one or more local folders/repos — projects "define the boundaries of the folders and repositories" the agent can access); center **conversation view** with a chat input; a **subagent panel** ("directly monitor the progress of any subagent by clicking into its conversation in the subagent panel"); and a **visual sidebar and review pane optimized for artifacts** — interactive plans, visual code diffs, and playable browser recordings.
- **Transcript:** the conversation/chat is the steering surface; you type a goal, then pick a **Mode in a setup modal** (Local mode = active folders; New worktree mode = isolated Git worktree). The design explicitly pushes *asynchronous* collaboration: "you don't need to carefully monitor every individual tool call… review high-level deliverables at key milestones" (artifacts).
- **Files/editor:** file search via ⌘P in 2.0; the full editor, terminal, and browser live in the **Antigravity IDE**, where agents "autonomously operate across the editor, terminal, and browser" and Tab autocomplete is the editing modality. The IDE is deprecated for enterprise (use 2.0/CLI).
- **Monitoring:** subagent panel for parallel background subagents (built-ins: `research`, `browser`, `self`; custom ones from `.md` files); **scheduled tasks via cron sidecars**; slash commands `/goal` (run to completion without intermediate input), `/grill-me` (clarifying questions before implementation), `/schedule`, `/browser`, `/plugin`; a Marketplace for plugins.
- **Navigation:** left sidebar (projects) + **⌘K conversation picker**, ⌘N new conversation, ⌥Up/Down next/previous conversation, ⌘L focus input — a command-palette-heavy keyboard model. CLI offers alt-screen (full-screen) vs inline rendering modes.
- **Workspaces/sessions:** projects (multi-folder, per-project isolated settings & security policies) → conversations/agents → worktrees for isolation; "work across multiple workspaces and worktrees" with parallel local subagents.
- **Focus/immersive:** no documented focus mode in 2.0; the CLI's alt-screen mode is the closest. The product philosophy is async milestone review rather than an immersive live view.

Sources: antigravity.google/docs/home/ · /docs/getting-started · /docs/subagents · /docs/artifacts · /docs/ide/overview (accessed 2026-10-11)

### 6. Cursor — agent panel in the IDE + Agents Window

- **Two surfaces since Cursor 3 (Agents Window GA 2026-04-02):** the **classic editor** (VS Code-based: file explorer left, editor center, terminal bottom) and the **Agents Window**, "Cursor's agent-first interface… a unified workspace to build with agents across repos and environments". You can switch between them (⌘⇧P → Open Agents Window / Open IDE) or run both simultaneously.
- **Where the agent panel lives (editor):** the Agent/Chat panel is a **sidepane opened with ⌘I** on the **right** side of the editor (official docs say "Access in sidepane with Cmd+I"; community reports confirm it is the right sidebar, which recent versions label "Agents"). The conversation timeline includes **checkpoints** — click one to preview/restore the codebase state at that point.
- **Agents Window layout:** a **left nav with a Projects section** (plus the parallel agents), a center conversation surface, and an **Agents Window-only diffs view** to "review and commit changes, and manage PRs without leaving Cursor". File access without leaving: ⌘P file search, ⌘⇧F search all files. Exact pane topology beyond these docs is unconfirmed.
- **Monitoring:** **parallel agents** run in the cloud and are managed from the Agents Window (also reachable from phone, web, Slack, GitHub, Linear); **Projects** are the unit for large bodies of work — a **coordinator agent plans and delegates** to many parallel agents, "open any agent the coordinator starts to follow its work or talk to it directly"; **subagents** run with isolated context windows, in foreground/background modes; `/in-cloud` hands a task to a cloud subagent, `/autopilot` puts a PR on auto-pilot (own VM + branch).
- **Workspaces/sessions:** multi-workspace in the Agents Window ("work with agents across all your projects from one place"); **worktrees** give each task its own isolated checkout; local↔cloud handoff moves an agent between your machine and the cloud.
- **Focus/immersive:** the Agents Window *is* the immersive agent surface (with an explicit escape hatch back to the editor); no separate focus mode documented.

Sources: cursor.com/docs/agent/overview · /docs/agent/agents-window · /docs/agent/projects · /docs/subagents (accessed 2026-10-11)

### 7. GitHub Copilot coding agent — mission/board UI on github.com

- **Where it lives:** entirely on **github.com** (plus Mobile, CLI, IDE hooks). Entry points: **issue/PR assignment** ("as easy as assigning an issue to a teammate"), the **agents panel** (available from *any* GitHub page, launched Aug 2025), **github.com/copilot/agents**, typing **`/task` in Copilot chat**, the home dashboard, and the Mobile agents task page.
- **Pane structure (Mission Control, Oct 2025):** a **centralized task view** — "instead of jumping between pages to track progress, monitor changes, and manage tasks, everything you need now lives in one streamlined, centralized view." The **session log sits right next to Overview and Files changed tabs** on the same page, with commit rationale in context.
- **Transcript:** the **session log** shows Copilot's reasoning and the tools it used (research, edits, tests in an ephemeral cloud dev environment). **Real-time steering:** a **chat input below the session log** (Copilot adapts when its current tool call completes), or inline comments in the Files changed view — "no more jumping to pull request comments to @copilot." Chat and cloud-agent sessions share context.
- **Files:** the **Files changed tab** shows the diff; from there you can request refinements or the PR. Full take-over: **open the session in Codespaces, VS Code (Insiders), or GitHub CLI**.
- **Monitoring:** the **task view** shows "task status at a glance" with quick task switching and quick links to the PR; the agents panel lists sessions (yours + others') with **token usage and session length**; the repo's **"Agents" tab** has an **"All sessions" view** (cloud sessions shared by default); commits are signed, authored by Copilot with a **link back to the session log**.
- **Navigation:** global agents panel (from any page), the /copilot/agents page, repo Agents tab, issue/PR pages — no dedicated standalone app; it is embedded in GitHub's existing navigation.
- **Workspaces/sessions:** **repos** are the unit; sessions are the tasks (the original "mission" framing from the 2025 launch; docs now say "sessions"); sessions can be stopped, archived, shared (view-only), and queried in natural language across synced sessions.
- **Focus/immersive:** none — the design goal was the opposite: one centralized page so you don't have to tab-hop.

Sources: docs.github.com/en/copilot/concepts/agents/coding-agent/about-coding-agent · /how-tos/.../manage-and-track-agents · github.blog/changelog/2025-10-28-a-mission-control-... (accessed 2026-10-11)

### 8. Factory (droids) — Factory App, web/mobile, CLI

- **Surfaces:** **Factory App** (desktop, app.factory.ai), **web + mobile** ("a native delegation interface that runs in the browser and on your phone"), and the **Droid CLI** (terminal-first). Sessions, Droid Computers (cloud VMs), MCP servers, and Skills **sync across all surfaces** — "start a task on one surface and finish it on another."
- **Pane structure (Factory App):** a dedicated visual workspace "organized around reviewing and refining whatever a session produces": **documents, presentations, spreadsheets, PDFs, live websites, and full code diffs render beside the session that produced them**. You set a working directory (project) and a model; sessions are **filterable and groupable across projects and machines**.
- **Transcript/steering:** session chat; **inline code review comments on a diff, line by line**, and a **design mode** (select an element in a live site and say what to change) — "Droid acts on the feedback in place." Mobile surface tunes the diff viewer, terminal output, and chat history for small screens; **shareable live session URLs** let teammates watch, comment, or take over.
- **Files/editor/terminal:** the app works directly on your local filesystem with your full dev environment; cloud work runs on **Droid Computers**; sessions can run in **separate git worktrees**.
- **Monitoring:** session lists grouped across projects/machines; notifications for completion and requested input; **subagents** (with their own notification sounds); a "Software Factory" layer coordinates multi-agent SDLC work (triage → code-gen → validation → documentation → monitoring) on schedules/triggers; sessions sync from Jira, Notion, Slack, Linear, PagerDuty.
- **Navigation:** project switching + session lists; delegation entry points from Slack/Linear/issues; CLI for terminal workflows. (Finer pane topology is not documented in the pages I accessed — flagged unconfirmed.)
- **Workspaces/sessions:** projects (working directories) + Droid Computers + worktrees; one synced session identity across desktop/web/CLI/IDE.
- **Focus/immersive:** settings include a **"sound focus mode"** and the ability to **hide the todo list** (plus unified/split diff view, line wrapping) — the closest documented equivalents to a focus mode.

Sources: docs.factory.com/ (llms.txt) · /factory-app/overview.md · /factory-app/quickstart.md · factory.ai/product/web (accessed 2026-10-11)

### 9. Zed — agent panel in the IDE

- **Pane structure:** Zed is a single IDE window with **two switchable panel layouts** — **"Agentic"** (Panel Layout > Agentic in the title-bar user menu, or `workspace: use agentic layout`) **places the Agent Panel and Threads Sidebar on the left, with the Project Panel, Git Panel, and other panels on the right**; **"Classic"** restores the editor-oriented layout. Individual panels can always be rearranged. (Notable: this is the inverse of the VS Code-family convention of docking chat right.)
- **Transcript:** the **Agent Panel** shows a *thread* (conversation): message editor, streaming responses with indicators showing which tools the model is using, editable/resubmittable messages, **queued messages** with a per-message **"Steer"** toggle (interrupt at the next step) and "Send Now". A **checkpoint / "Restore Checkpoint"** button appears at the top of messages that edited files. **Terminal threads** run inside the Agent Panel itself.
- **Files/editor/terminal:** classic IDE surfaces — project file tree (Project Panel), editor tabs, Git Panel, terminal; a **worktree picker in the title bar** selects/creates the Git worktree a thread runs in.
- **Monitoring:** the **Threads Sidebar** (⌘⌥J) lists **all threads grouped by project** with title, **status indicator**, and which agent is running; ⌃Tab cycles recent threads without opening it; **Thread History** (⌘G, clock icon) holds archived threads and can restore them (recreating a removed worktree automatically). Sidebar position/width are settings.
- **Navigation:** **command palette** (`agent: new thread`, `workspace: use agentic layout`, …), the ✨ status-bar icon, threads sidebar, ⌃Tab. External (ACP) agents such as Claude Code/Codex appear in the same "New Thread…" menu, and their existing threads can be imported into Thread History.
- **Workspaces/sessions:** *projects* (opened folders/worktrees) are the grouping unit; each thread has its own agent, context window, and history; **worktree isolation** keeps parallel threads from editing the same files.
- **Focus/immersive:** the **Agentic layout** is the immersive mode (agent surfaces left, code panels right); no separate fullscreen focus mode documented.

Sources: zed.dev/docs/ai/agent-panel · zed.dev/docs/ai/parallel-agents (accessed 2026-10-11)

### 10. Cline (VS Code extension) — side-panel pattern

- **Where the panel lives:** Cline is an **Activity Bar icon** (a small robot) in VS Code/Cursor/Windsurf; the docs note it **opens in the left sidebar by default (replacing the file explorer) and explicitly recommend dragging it to the right sidebar** so "you can keep your project files visible on the left while chatting with Cline on the right, so you can watch your workspace change as Cline works." JetBrains opens it on the right (View → Tool Windows → Cline).
- **Panel structure:** a **chat interface** — "a text input box at the bottom where you type messages, a chat area above it where Cline's responses will appear, and a settings gear icon in the top-right corner." `Cline: Open In New Tab` opens it as a **full editor tab** for more screen space. Plan mode and Act mode are the two working modes (plan = no file-editing tools; act = edits + commands), with per-action approval gates and auto-approve settings.
- **Files/terminal:** Cline uses the host editor's own file explorer, editors, and terminal; its tools read/write files and run commands in the opened workspace folder (a folder must be open for Cline to know where to work). It also has an in-panel **browser** tool for web tasks.
- **Monitoring (beyond the panel):** **Cline Kanban** (`npx kanban`) is a **web-based task board** for parallel agents: create cards (manually or "from sidebar chat"), each card gets an **isolated git worktree + terminal**, you **monitor progress from card status and latest agent output**, **review diffs in the card detail view with inline comments**, then Commit/Open PR from the card; task linking creates dependency chains that auto-start next tasks. **Cline Desktop** is a dedicated app with **parallel sessions** (per-session workspace + branch), scheduled tasks, and a Marketplace.
- **Navigation:** Activity Bar + command palette in the IDE; the board/desktop apps have their own navigation (card lists, session lists).
- **Workspaces/sessions:** the **opened folder is the unit** in the IDE; in Desktop/Kanban, sessions/cards each carry their own workspace, branch, and worktree.
- **Focus/immersive:** no documented focus mode; the "open in new tab" option is the closest (more space for one conversation).
- **Subagents:** available in CLI/Desktop only — `spawn_agent` spawns parallel research subagents with isolated context windows that return reports to the main agent; approving the spawn approves everything the subagent does. The VS Code extension doesn't use them.

Sources: docs.cline.bot/usage/ide · /usage/kanban · /usage/cline-desktop · /features/subagents · /cline-overview (accessed 2026-10-11)

### 11. CLI/TUI agents — the "no GUI" reference point

- **Shared layout (all four):** the entire interface is a **single scrolling transcript in the terminal with the input prompt at the bottom** — no panes, no side lists, no boards. Session management is by commands/flags, and durable state lives in git, not in UI. This is the baseline every GUI above is adding structure on top of.
- **Claude Code** (`claude`): terminal TUI as the primary surface, plus IDE extensions, a desktop app, and **Claude Code on the web** (claude.ai/code) / mobile for cloud sessions. Cloud sessions "keep running after you close your laptop, and you can check on it or steer it from any device"; sessions move between terminal and cloud via `--cloud`/`--teleport`; **projects** group "many cloud sessions for one body of work"; **routines** run scheduled/triggered cloud sessions.
- **Codex CLI** (`codex`): "one focused terminal loop for interactive work, automation, review, and delegation"; `codex resume` reopens recent chats (searchable across local chats); `codex exec` for scripts/CI; `/permissions` sets sandbox/approval boundaries; **subagents** delegate and "bring their findings back into the main terminal session"; `codex cloud` lets you **browse active and completed chats from the terminal** and submit work to a cloud environment; web-search activity "stays visible in the transcript."
- **Aider**: terminal pair-programming bound to a **git repo** — auto-commits changes "with sensible commit messages"; **in-chat commands** (`/add`, `/model`, …) and **chat modes** (code, architect, ask, help); **notifications when it's waiting for your input**; an experimental **`--browser` web UI** to "chat with Aider AI like it's a fancy app… great for… juggling multiple tasks" — i.e., Aider's own answer to the no-GUI problem is a thin web chat, not a pane layout.
- **Goose** (Block): CLI + desktop app; the CLI manages **sessions** (ids, resume), **extensions** (MCP servers as plugins), and **recipes** (reusable, shareable task templates); multi-provider. The TUI is a chat transcript; extensions/recipes are configured via commands and config, not GUI.
- **Takeaway for a GUI:** the CLI group validates that (a) the transcript is the primary surface, (b) sessions must be resumable/listable, (c) git is the source of truth for file state, and (d) the missing pieces that GUIs add are *parallel* session visibility, *steering while running*, and *diff/artifact review* — none of which the terminal can show well at once.

Sources: code.claude.com/docs/en/overview · /en/claude-code-on-the-web · learn.chatgpt.com/docs/codex/cli.md · aider.chat/docs/ (+ /docs/usage/browser.html) · goose-docs.ai/ (+ /docs/guides/goose-cli-commands) (accessed 2026-10-11)

## Synthesis

### Common patterns (what the industry converges on)

1. **Sessions/conversations in a left list, transcript center.** Every full-surface product puts the session/conversation list in a **left sidebar** and the transcript in the **center** (Devin, OpenHands, Codex, Jules-per-repo, Antigravity 2.0, Cursor Agents Window, Factory, Zed, Cline). This is the single strongest convergence in the research and directly validates tau's *sessions-first left list*.
2. **A distinct "files/diff/artifact" surface beside the transcript, not inside it.** Files, diffs, and artifacts consistently live in a **separate pane/drawer/tab** adjacent to the chat — a right drawer (OpenHands Files/Commits), a side review pane (Antigravity artifacts, Factory "render beside the session"), tabs (Devin Changes/PR, Copilot Files changed), or a diffs view (Cursor Agents Window). Validating tau's *right dock for files/tasks*.
3. **Parallelism is the core new problem, solved with lists + isolation, not boards.** Running agents are monitored via a **list of threads/sessions with status** (Zed Threads Sidebar, Codex sidebar, Devin sidebar, Cursor) plus **git-worktree isolation** per task (Zed, Cursor, Cline Kanban, Antigravity, Codex). The kanban *board* exists but is a secondary/optional surface (Cline Kanban, Copilot's task view), not the primary layout.
4. **Steering-while-running is a first-class, in-composer feature.** Queue-then-send, "Steer" toggles, and follow-up inputs that apply when the current tool call finishes appear across Devin (queued messages), Zed (queued + Steer), Codex (real-time steering), Copilot (real-time steering), Factory, Cursor. This validates tau's *steering queue* in the composer.
5. **Workspaces/projects are the top-level container; sessions nest under them.** Projects (Cursor, Antigravity, Zed, Claude Code) or repos (Jules, Copilot) group sessions, with per-project settings/isolation. Worktrees are the standard mechanism for parallel isolation. Validates tau's *multiple workspaces* as a first-class, top-level concept.

### Notable outliers

- **Zed's "Agentic" layout inverts the convention**: agent panel + threads sidebar on the **left**, file/git panels on the **right** — the mirror image of the VS Code-family "chat right, files left" default (Cursor, Cline). Worth noting: the field is split on which side the *conversation* docks, with the session *list* more consistently left.
- **Google Antigravity 2.0** is the most radical: it de-emphasizes the live transcript in favor of **async artifacts** (plans, diffs, browser recordings) reviewed at milestones, with a dedicated subagent panel and cron-scheduled tasks. It treats the GUI as a *command center / review surface*, not a live chat window.
- **GitHub Copilot** has no standalone app at all — the "board" (Mission Control) and agents panel are **embedded in github.com's existing navigation**, with the repo as the container and PRs as the primary artifact. It is the "agent as a teammate in your existing tool" extreme.
- **Cline** is the purest *side-panel-in-a-host-IDE* pattern, and its docs actively steer users to move the panel to the right so files stay visible — i.e., the panel is an add-on, and the host IDE's file tree/editor/terminal remain primary.
- **The CLI group** is the reference floor: one scroll, prompt at bottom, git as source of truth. Notably, even Aider's "fancy" escape hatch is a thin web *chat*, and Claude/Codex add web/mobile *companions* mainly for **listing and steering cloud sessions** — confirming that the GUI's job is parallel-session visibility + steering + diff review, not re-rendering the transcript.

### Implications for tau's chat-first desktop GUI

- **Validated by the industry:** (a) sessions-first **left list**; (b) **right dock** for tasks/sub-agents/files; (c) **steering queue** in the composer; (d) **workspaces as top-level containers** with sessions nested and worktree isolation; (e) a **command palette** (⌘K) for cross-cutting navigation — Devin, Antigravity, Zed, Cursor all center on it.
- **Unusual / under-validated — treat as a differentiator to justify, not a default:** (a) a **topbar workspace switcher** — most products make the workspace/project the *container of the left list* (a project header or a projects section in the sidebar) rather than a topbar control; a topbar switcher is defensible but is not the dominant pattern. (b) **Focus mode with edge pill rails** — no product documents a dedicated focus/immersive *layout mode* with edge rails; the closest analogs are collapsible/peek sidebars (Devin, Codex), Zed's Agentic/Classic layout switch, and Factory's "sound focus mode" (which is audio, not layout). Tau's focus mode is therefore a genuine differentiator: it should collapse the left list and right dock to slim edge rails that expand on hover, which is consistent with the *hideable-sidebar/peek* behavior several products already ship, just applied to both rails at once.
- **Design guidance from the outliers:** keep the live transcript primary (the Antigravity async-artifacts model is a different product philosophy, not a signal to demote the transcript), and consider a **secondary board view** (Cline Kanban / Copilot task view) for heavy parallel-fanout users rather than making the board primary. Sub-agent monitoring is best served by a **dedicated panel/list of child conversations** (Devin nested tree, Antigravity subagent panel, Cursor projects) nested under the parent session, which matches tau's right-dock sub-agent surface.
