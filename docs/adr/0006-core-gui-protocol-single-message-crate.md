# Core↔GUI protocol: one message-crate surface, core-owned state

**Context**: ADR-0002 makes `tau-core` a standalone library with a future CLI/RPC boundary. Research #13 showed the remote-GUI question reduces to six v0 constraints (serializable message set, core-owned state, no local paths as identity, idempotent streaming, HITL pair, no Tauri types in the core). Ticket #10 settles the in-v0 shape of that boundary.

**Decision**: the core↔GUI boundary is **one shared crate of tagged-union messages** (commands in, events out). Tauri commands/events are transport #1 carrying those same types; the Svelte side compiles against the protocol types alone — there is no richer in-process API. In v0: **no protocol version field** (added before v1, while breaking is free) and **no HITL request/response** (deferred with the security model; questions = the model ends its turn, the user answers in the composer).

- **State ownership**: the core is the single owner of all session/workspace/task state; the GUI is a stateless renderer, rebuildable from a **snapshot projection** + the event stream. The snapshot is *ephemeral* (never a file): session metadata + entry *metadata* tree (id, type, timestamp, size, preview — no payloads) + the bounded OM observations log + live state (queue, sub-agents, tasks, turn) + cursor. A 10k-entry session snapshots in ~1–2 MB.
- **Streaming**: deltas coalesced at 25 ms; tool output idempotent-cumulative, correlated by stable ids; every message carries workspace + session id over one multiplexed channel; no shared memory or file watching across the boundary.
- **Reads are paged** (`entries {range}` / `entries-since {cursor}`); the GUI virtualizes (no rendering beyond the viewport + scroll buffer); sidecar blobs (ADR-0005) stream on demand; archived spans render collapsed.
- **Identity**: no local paths as identity — a **workspace** object (id, name, cwd-on-host); tool args are absolute or workspace-relative paths on the host's filesystem (no sandbox in v0 — security model is fog).
- **Sub-agents**: child sessions are ordinary sessions (openable/steerable/branchable in the GUI). Parent tools `subagent_spawn/message/stop/resume/state` — no force (user-only). Child tools `parent_notify {text, done?, output?}` (done = terminal, schema-gated, resolves any assigned task as completed/handed_off/blocked) + `recall`. One-shot nudge on turn-end-without-done; states **running / idle (explicit `waiting_on`) / done / failed (auto-notifies the parent) / stopped (provenance)**; all deliberately resumable, nothing auto-resumes; `waiting_on: parent` (and done/failed) wake a parked parent; parent closed → children pause.
- **Agent types**: built-in `general` + `.md` files — `~/.config/tau/agents/` (system), `{project}/.tau/agents/` (project wins); frontmatter = name/description/tools/model/default context-mode; body = system prompt.
- **Tasks**: per-workspace, **event-sourced** (replayable; snapshot = the resume contract); enforced state machine; steps with expected outputs; acceptance criteria; **evidence-gated completion** with no model-facing category enums (evidence = criterion ref + summary + optional command/artifact + passed; display types derived in the GUI); free-text blockers; decisions ledger; the **resume contract** is re-injected on every compaction of a session holding an active task.
- **read/edit are hash-anchored** per the pi-better-edit scheme (the SOTA from "The Harness Problem", +15 pts over patch across 16 models): 3-char anchors from a 62-char alphabet, uniqueness *allocated* (bitset + probe; 238k-line cap → `write`), whitespace-stripped canon, stable reuse across edits, stale/ambiguous anchors rejected, never fuzzy-matched.

**Consequences**: a future remote backend is a `tau serve` binary + browser client over the *same* types (auth/multi-client ship with it); the GUI's task panel, agent-type picker, and live child-session view are pure renderings of protocol state; ADR-0002's no-Tauri-types rule becomes review-enforceable; the GUI performance bar (10k-entry session + two live child streams, no lag) is a property of the protocol, not the renderer.

**Considered**: a rich in-process API with the protocol as a projection (two surfaces, guaranteed drift); ad-hoc Tauri command signatures (kills the remote-ability argument); a protocol version field in v0 (user: we're prototyping, pre-v1 is breakable); mid-turn HITL request/response (user: no restrictive security model in v0); category enums on evidence/blockers (model-failure surface with no rigor payoff — the gate and linkage carry the rigor).
