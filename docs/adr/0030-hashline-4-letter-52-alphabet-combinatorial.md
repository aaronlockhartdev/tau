# Hashline anchors are 4 letters from a 52-letter alphabet, computed combinatorially

**Status**: accepted (2026-12-04) — the format revision of issue #202 (items 1 + 4).

The hash-anchored read/edit contract (spec §5.4, ADR-0006) shipped with 3-char anchors from a 62-char alphabet (A–Z, a–z, 0–9): 62³ = 238,328 slots, base `xxh32(canon) >> 14 % 62³`, probe stride 3907 (62²+62+1). Two defects motivate the revision. **Token churn**: a local tiktoken check showed the 3-char alphanumeric anchors split into 1–3 tokens (avg 2.2–2.3) — a digit inside the anchor breaks the merge that letters-only strings get on the tokenizers we measure. **Unbounded hash input**: `canon(line)` is hashed in full, so a minified line (hundreds of KB) makes every read of that file pay a full-line hash — the reference implementation (pi-hashline-edit-pro) caps the hash source at 500 bytes for exactly this reason.

**Decision**: anchors are 4 letters from a 52-letter alphabet (A–Z, a–z — no digits): `HASH_SPACE = 52⁴ = 7,311,616`. The slot→string encoding is **combinatorial, not tabulated**: a slot index encodes as positional base-52 over the alphabet (`idx_to_hash`/`hash_to_idx` are div/mod), a bijection over the whole space with no data file — the reference's 1.35M-entry 5.4 MB `anchor-table.json` is not ported. The base slot is `xxh32(hash_source) >> 14 % 52⁴` (a u32 comfortably holds 7.3M, so the `>> 14` high-bits reduction is retained unchanged); the probe stride is `HASH_SPACE − 3` (≡ −3 mod 52⁴, coprime — the same coprime family as the old stride). The **hash source** is the canon truncated to 500 bytes at a UTF-8 char boundary (`MAX_HASH_SOURCE_BYTES`): two lines sharing a 500-byte canon prefix share a base slot, and allocation probing keeps their anchors unique as before. The 7.3M-slot space lifts the line-count cap from 238k to 7.3M (the `write` fallback is now effectively unreachable).

**Considered**: keep 62²·62 and just drop digits — rejected: that shrinks the space to 52³ = 140k, worse than before. Port the reference's table — rejected: 5.4 MB of data for what div/mod computes for free; the combinatorial encoding is deterministic, versionable in one line, and the bijection is covered by a test over all 7.3M slots. A 53+ letter alphabet (digits back in) — rejected: the whole point is letters-only token stability.

**Consequences**: every 3-char anchor literal in fixtures, goldens, prompts, and tests changes shape in the same change (the acceptance-tools mock re-pins to a computed 4-letter anchor); the frontend diff parser (`diffview.ts`) moves its anchor slice one column; the stale/anchor-detection checks (`is_anchored_content`, `BadAnchor`) test length 4 and letters-only. `hash_source` is a new public function (the truncation rule is part of the anchor-identity contract). One-time break: saved sessions show stale anchors after upgrade until re-read — expected for a format revision, no migration. The `>> 14` reduction is retained (not the reference's quirk justification) because it bounds the base-slot range cheaply and the stride probe covers the rest; the coprimeness of `52⁴ − 3` is asserted in `hashline/tests.rs`.
