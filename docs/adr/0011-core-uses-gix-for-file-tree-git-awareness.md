# The core uses gix (gitoxide) for file-tree git awareness

**Status**: accepted (2026-10-13) — formalizes a choice the `git.rs` header had misattributed to ADR-0002.

The file-tree git awareness (the badge on each file, the changes-tab numstat, the gitignore greying, and the file-content view's diff base) shelled out to the `git` CLI — five spawns per snapshot (`status`, `diff --numstat`, three `ls-files` variants), cached per workspace and rebuilt on every debounced `file_tree_changed`. It hit two walls. **Scale**: `git ls-files --others` enumerates *all* 467,438 files under `target/` in this repo into a `HashSet` on every refresh, and `dir_prefixes` runs over all 467k paths. **Invisibility**: `.tau/skills` is an *empty* ignored directory, so `ls-files` never mentions it and the set-difference model that computes "is this folder all-ignored" structurally cannot see it — no tuning fixes that.

**Decision**: the core links `gix` (the pure-Rust git library gitui is built on) and computes the snapshot in-process, with `similar` for the line-diff numstat. The status split comes from `repo.status().into_iter()`, whose dirwalk **prunes ignored directories** — `target/` is greyed and never descended into, so the 467k files are never enumerated (the status walk measures 46–61 ms here, versus the ~5 s shell-out rebuild). Numstat line-diffs each *modified* file's HEAD blob against its worktree copy (a bounded set — the ignored files never appear in the status), and counts lines for untracked files. Greying loads the ignore patterns once (`info/exclude` + the root `.gitignore`) into an `ignore::Search` and greys a path when it *or any ancestor directory* matches — the rule that greys an empty ignored dir (`.tau/skills`) just like its ignored parent (`.tau/`). `git_show` reads the HEAD blob by walking the tree with `find_entry` per path segment (gix has no `find_file`).

**Considered**: keep the shell-out and only prune the `ls-files` enumeration — rejected: the set-difference model still cannot see empty ignored dirs, and five subprocess spawns per debounced refresh *is* the freshness bottleneck. Use `git2` (libgit2 bindings) — rejected: `gix` is pure Rust (no C linkage in the core) and is the library gitui uses for exactly this file-tree use case, so its API is proven for it.

**Consequences**: `gix` and `similar` are new `tau-core` dependencies (sizeable compile time; acceptable for a Tauri app that already links a webview). The wire contract — `GitStatus`, `FileEntry`, `FileGit`, `CommandOutput::GitShow` — is byte-identical, so the frontend is untouched. The dead `git_diff` command (no frontend caller) is deleted end to end. Nested `.gitignore` files are folded into the same `Search` as the root one and `info/exclude` by a pruned worktree walk: it adds each file scoped to its own directory (the search `base`) and skips dirs the search already ignores, so it never descends into e.g. `target/`, and greying honours a pattern from any depth (git's closest-`.gitignore`-wins falls out of the search's reverse-iteration match order). The status walk uses gix's full ignore machinery internally for untracked enumeration regardless. The `git.rs` header's earlier claim that "the core keeps no git library dependency (ADR-0002)" was a misattribution — ADR-0002 is the single-process model and says nothing about git. No prior ADR is reversed; this one records the new choice.
