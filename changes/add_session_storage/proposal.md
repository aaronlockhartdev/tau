# Design session storage

## Context

A session is an append-heavy log that must survive a restart, with working state on top: anchor rows for the edit tools, observational memory's observations and reflections, approvals, per-session prompt prefixes. Sessions are listed, resumed, forked, and compacted over days, read by two frontends through core and queried by the eval harness. A shape where one fact lives in two places costs a reconciliation path, and that path runs on the worst day of all: the crash.

## Options

- A. One SQLite store (`rusqlite` 0.41.1, `bundled`, WAL): an append-only `events` table as the log, plus mutable state tables for anchors, memory, approvals, and prefixes. One transaction per event. Evidence: [crates.io](https://crates.io/crates/rusqlite), 2026-11-13; [`libsqlite3-sys` build.rs on master](https://github.com/rusqlite/rusqlite/blob/main/libsqlite3-sys/build.rs) (read 2026-11-13) enables `SQLITE_ENABLE_FTS5`, `JSON1`, `RTREE`, `STAT4`; [sqlite.org/wal.html](https://sqlite.org/wal.html) (read 2026-11-13) gives one writer at a time, all processes on one host, no WAL over a network filesystem; OpenCode runs its sessions from one SQLite database at `~/.local/share/opencode/opencode.db` ([agent-sessions survey](https://jazzyalex.github.io/agent-sessions/blog/where-agents-store-history/), read 2026-11-13). Cost: a C build, `sqlite3` to inspect by hand, an export command for text views, and fork and compaction as row copies.
- B. Files only: one JSONL per session, state as records appended to the same file and folded in memory at open. Evidence: pi's live layout at `~/.pi/agent/sessions/--<cwd>--/<ts>_<uuid>.jsonl` with a first record carrying `parentSession` as a path (inspected 2026-11-13), plus Claude Code, Codex, and Copilot ([agent-sessions survey](https://jazzyalex.github.io/agent-sessions/blog/where-agents-store-history/), read 2026-11-13). Cost: no dependency and live grep, and every query is a scan: the session list reads the first record of every file, search reads gigabytes (this machine holds 3.5 GB of pi sessions), and a mutation such as a consumed anchor is an append and a fold, with no point update and no index.
- C. Hybrid, event-sourced: the JSONL transcript is authoritative, the database holds state rows keyed by event id with each row written once, and opening a session replays the transcript tail. Evidence: as B for the log, as A for the store. Cost: content lives in exactly one place, and the price is an ordering rule (append, then apply), idempotent replay code, and a schema rule that no transcript text enters the database, which forecloses full-text session search.
- D. Hybrid with a derived index: transcript files, and SQLite tables mirroring sessions, events, offsets, and full-text over transcript text. Evidence: the Cursor and Hermes splits in the [agent-sessions survey](https://jazzyalex.github.io/agent-sessions/blog/where-agents-store-history/) (read 2026-11-13) are this shape, and the survey reports that reading one of Cursor's stores gives half the picture. The crash-path cost is a deduction from that shape: the index copies transcript content, so the crash path has to rebuild it, which is the reconciliation this design refuses.

Performance settles nothing here. [redb's benchmark](https://github.com/cberner/redb) (README, read 2026-11-13) measures one fsync per commit and reports SQLite as the slower of the two by a wide margin. [sqlite.org/pragma.html](https://sqlite.org/pragma.html) (read 2026-11-13) states that in WAL mode `synchronous = NORMAL` syncs less often than FULL, stays consistent, and keeps transactions durable across application crashes, giving up durability only across a power or system crash. tau's event rate is `unverified` at tens of events per second with a model call dominating each turn, so every option here clears the workload.

## Decision

A. `.tau/state.db`, SQLite via `rusqlite` (`bundled`, WAL). Separation of duties is by schema: the `events` table is append-only, rows never updated, and the mutable tables hold anchors, observations, reflections, approvals, and prompt prefixes. One transaction per event, so a tool call commits its event and its state change together, and no fact has two owners.

Export is a command (`tau sessions export <id>` writes JSONL), and text views exist for eval and logs while the store stays unread by hand.

## Consequences

`crates/tau-core/storage` owns the schema and its migrations, and [`rusqlite_migration` 2.7.0](https://crates.io/crates/rusqlite_migration) requires [`rusqlite` ^0.41](https://crates.io/crates/rusqlite) (crates.io, 2026-11-13), so migrations start at 0.41. Core owns the single write connection, and storage work runs on its own task: an event reaches frontends from core's in-memory stream, per the live-output invariant in `spec/index.md`, so a write, a checkpoint, or a busy reader never gates the GUI. Readers (the ACP frontend, the eval harness, export) take short read transactions and never hold one open across a turn, which is what keeps the checkpoint working: [sqlite.org/wal.html](https://sqlite.org/wal.html) (read 2026-11-13) auto-checkpoints at 1000 WAL pages and truncates the log only when `journal_size_limit` is set, so a reader that holds a read transaction open stalls the checkpoint and grows the log. With `synchronous = NORMAL` a committed turn survives an application crash and can roll back after a power loss, and the behaviour lane's crash case is one assertion: a committed turn is present in full after a restart. Fork is an `insert … select` over an event range plus a parent id, and compaction appends a summary event and marks the visible range. Session search runs on FTS5. The eval harness queries the store instead of parsing a per-tool format, which is the reason the survey of agent storage needed a parser per tool. A project on a network filesystem is unsupported, since WAL needs shared memory on one host. Tapes stay authored text in the behaviour lane, and JSONL stays in logs, per `add_user_config`. Storage adds no wire shape, so `contracts/` is untouched. The reader rule and the crash assertion land as `R-SESSION-NN` in `spec/session/storage/spec.md`.

Eval: none needed. Storage is deterministic and covered by the behaviour lane.

Open: none.
